Executive Summary

In Tauri v2, building transparent, click-through overlay windows that sit on top of the entire operating system requires precise configuration of Tauri's WebviewWindowBuilder and the set_ignore_cursor_events system API.

A key issue in standard overlay implementations is the white-screen startup flash. On Windows, when a webview window is loaded, the Edge WebView2 control initially initializes with a default white background before parsing the page CSS. To bypass this, we configure the window with visible: false, allow it to initialize in the background, and programmatically invoke window.show() only after the capture loop is armed (~1 second later). This guarantees a completely transparent presentation.

Tauri v2 Overlay Config Recipe

The window must be configured with specific attributes to prevent focus stealing, hide taskbars, and support transparency:

let overlay = tauri::WebviewWindowBuilder::new(
    &app,
    "effects-overlay",
    WebviewUrl::App("/overlay.html".into()),
)
.title("EasySpecy Effects")
.inner_size(logical_width, logical_height)
.position(0.0, 0.0)
.decorations(false)        // Removes titlebars, borders, window frames
.transparent(true)          // Allows underlying desktop / other apps to be seen
.always_on_top(true)        // Keeps overlay on top of standard windows
.skip_taskbar(true)         // Hides it from Windows taskbar & Alt+Tab list
.resizable(false)
.focused(false)             // CRITICAL: prevents grabbing window focus on startup
.visible(false)             // CRITICAL: prevents white background startup flash
.build()?;

// CRITICAL: Makes the window click-through so user can interact with apps behind it
let _ = overlay.set_ignore_cursor_events(true);
Frontend CSS Requirements

The webview itself must also have zero background color, or else standard styles will paint a solid white/gray sheet:

html, body {
  width: 100%;
  height: 100%;
  background: transparent !important; /* Zero opacity */
  overflow: hidden;
  user-select: none;
  -webkit-user-select: none;
}

canvas {
  position: fixed;
  top: 0;
  left: 0;
  width: 100vw;
  height: 100vh;
  pointer-events: none; /* Passes mouse clicks down */
}
IPC Architecture & Event Delivery

Because click-through windows ignore mouse inputs (pointer events), the overlay cannot listen to normal web DOM mousemove or mousedown events. Instead, we use Tauri's IPC event bus:

Input Type Rust Capturer Tauri Event / Call Frontend Render Reaction
Mouse Move Low-Level Hook / Win32 API cursor-move event Injects point into Catmull-Rom spline trail buffer, draws to Canvas.
Mouse Click Low-Level Hook / Win32 API cursor-click event Triggers ripple, pulse, spotlight, or confetti rendering.
Keyboard WH_KEYBOARD_LL (hook thread) get_keyboard_events command Frontend polls at 20Hz, updates horizontal text bubbles overlay.
