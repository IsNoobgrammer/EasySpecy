Executive Summary

The keyboard overlay fails to capture keystrokes when a game window (e.g., Dead Cells) is focused, despite working perfectly during normal desktop operations (like file navigation or standard text entry). This is not a bug in the application logic; rather, it is a restriction enforced by Windows security privileges (UIPI) and the direct-input retrieval mechanisms used by games.

Because launchers (Steam, Epic Games) or game executables often run with elevated (Administrator) permissions, Windows protects their inputs from non-elevated applications to prevent security tampering. Furthermore, games bypass the Win32 message loop entirely via Raw Input or DirectInput APIs, meaning the hook callback (which relies on Windows message pumps) receives no events.

Primary Causes Breakdown

1. User Interface Privilege Isolation (UIPI)

Windows protects higher-integrity (elevated/admin) processes from lower-integrity (standard) processes. If your game or launcher runs as Administrator, a standard user application's low-level hook (WH_KEYBOARD_LL) is strictly blocked by the OS from capturing keys typed while that elevated window is focused.

2. Hardware-Direct Input Bypassing

Games require low-latency inputs. They often query keyboard states directly from drivers via Raw Input or DirectInput. Because WH_KEYBOARD_LL hooks standard thread/window messages, it misses hardware-direct calls completely.

3. Anti-Cheat Hook Suppression

Kernel-level anti-cheat services block user-mode hooking APIs (like SetWindowsHookEx) to prevent macro engines and automated cheat execution.

Actionable Workarounds & Solutions

Option A: Run EasySpecy as Administrator (Immediate Fix)

By running EasySpecy with Administrative privileges, its integrity level matches the game's, allowing the low-level hook to successfully intercept inputs.

Action: Right-click the EasySpecy shortcut or executable and choose "Run as administrator".

Option B: Use Raw Input API (Developer Action)

Instead of a Windows hook, register a Raw Input keyboard listener in Rust. It captures input hardware-level states even for games that bypass standard messages.

Action: Register RegisterRawInputDevices with RIDEV_INPUTSINK in the Rust backend.
