Executive Summary

Auto-zoom in screen recording is a solved problem at the heuristic level — every major competitor uses the same core signal: mouse clicks. The differentiation is in smoothing, timing, and fallback heuristics. The industry consensus (confirmed across 8+ products) is:

  1. Primary trigger: Mouse clicks (especially 2+ clicks within a 3-second window)
  2. Secondary trigger: Cursor activity density (dwell time, movement clustering)
  3. Tertiary trigger: Active window change / foreground window bounds
  4. Smoothing: Spring-physics interpolation for camera movement (not linear lerp)
  5. Rendering: Post-processing crop+scale (NOT FFmpeg zoompan — too limited for dynamic coordinates)

For EasySpecy specifically: you already have cursor position data from your trail system. The auto-zoom is a natural extension of your existing post-processing pipeline — same data, different rendering pass.

Recommended Heuristic Algorithm for EasySpecy

The Multi-Signal Zoom Decision Engine

Based on cross-referencing all competitor approaches, here's the recommended algorithm that fits your existing architecture:

Phase 1: Data Collection (During Recording — You Already Have This)

Your cursor trail system already collects timestamped cursor positions. Extend it to also capture:

struct ZoomEvent {
    timestamp: Duration,      // relative to CAPTURE_ARMED
    position: (i32, i32),     // cursor screen coords
    event_type: EventType,    // Click, Move, Scroll, KeyPress
    window_bounds: Option<Rect>,  // active window rect at this moment
    window_title: String,     // for debugging/display
}

enum EventType {
    LeftClick,
    RightClick,
    DoubleClick,
    Scroll { delta: i32 },
    KeyPress,
    CursorMove,
}

Phase 2: Post-Recording Analysis (The Heuristic Engine)

Signal 1: Click Clustering (Primary — highest confidence)

// Cursorful's rule: 2+ clicks within 3 seconds = zoom trigger
fn detect_click_clusters(events: &[ZoomEvent]) -> Vec<ZoomRegion> {
    let clicks: Vec<&ZoomEvent> = events.iter()
        .filter(|e| matches!(e.event_type, EventType::LeftClick | EventType::DoubleClick))
        .collect();
    
    let mut regions = Vec::new();
    let mut cluster_start = 0;
    
    for i in 1..clicks.len() {
        let time_gap = clicks[i].timestamp - clicks[cluster_start].timestamp;
        
        if time_gap > Duration::from_secs(3) {
            // End of cluster — if 2+ clicks, emit zoom region
            if i - cluster_start >= 2 {
                let bounds = bounding_box(&clicks[cluster_start..i]);
                regions.push(ZoomRegion {
                    start: clicks[cluster_start].timestamp - Duration::from_millis(500),
                    end: clicks[i-1].timestamp + Duration::from_secs(1),
                    center: bounds.center(),
                    zoom_level: calculate_zoom(bounds),
                });
            }
            cluster_start = i;
        }
    }
    regions
}

Signal 2: Cursor Dwell / Activity Density (Secondary)

// Screenforge's approach: find regions of dense cursor activity
fn detect_activity_hotspots(events: &[ZoomEvent], window_secs: f64) -> Vec<ZoomRegion> {
    // Sliding window: count events per spatial grid cell
    let grid_size = 200; // pixels per cell
    let mut heatmap: HashMap<(i32, i32), Vec<Duration>> = HashMap::new();
    
    for event in events {
        let cell = (event.position.0 / grid_size, event.position.1 / grid_size);
        heatmap.entry(cell).or_default().push(event.timestamp);
    }
    
    // Find cells with sustained activity (>N events in window_secs)
    let threshold = 10; // events per window
    let mut hotspots = Vec::new();
    
    for (cell, timestamps) in &heatmap {
        for window in timestamps.windows(threshold) {
            let duration = window.last().unwrap() - window.first().unwrap();
            if duration < Duration::from_secs_f64(window_secs) {
                hotspots.push(ZoomRegion {
                    start: *window.first().unwrap() - Duration::from_millis(300),
                    end: *window.last().unwrap() + Duration::from_millis(500),
                    center: (cell.0 * grid_size + grid_size/2, 
                             cell.1 * grid_size + grid_size/2),
                    zoom_level: 2.0, // configurable
                });
                break; // one hotspot per cell
            }
        }
    }
    hotspots
}

Signal 3: Active Window Focus (Your "Intelligent Window Detection")

// Track foreground window changes — zoom to window bounds when user focuses
fn detect_window_focus_zooms(events: &[ZoomEvent]) -> Vec<ZoomRegion> {
    let mut regions = Vec::new();
    let mut current_window: Option<&str> = None;
    let mut focus_start: Option<Duration> = None;
    
    for event in events {
        if let Some(bounds) = &event.window_bounds {
            let title = &event.window_title;
            
            if current_window.map_or(true, |w| w != title.as_str()) {
                // Window changed! If previous focus was >2s, emit zoom
                if let Some(start) = focus_start {
                    if event.timestamp - start > Duration::from_secs(2) {
                        // User was focused on previous window for >2s
                        // Zoom to that window's bounds
                        regions.push(ZoomRegion {
                            start,
                            end: event.timestamp,
                            center: bounds.center(),
                            zoom_level: calculate_zoom_for_window(bounds, screen_size),
                        });
                    }
                }
                current_window = Some(title);
                focus_start = Some(event.timestamp);
            }
        }
    }
    regions
}

fn calculate_zoom_for_window(window: &Rect, screen: &Size) -> f64 {
    // Zoom level = how much of the screen the window occupies
    // If window is 50% of screen width, zoom 2x to fill
    let width_ratio = screen.width as f64 / window.width as f64;
    let height_ratio = screen.height as f64 / window.height as f64;
    width_ratio.min(height_ratio).min(4.0).max(1.2) // clamp 1.2x-4x
}

Signal 4: Typing Detection (Zoom to text input area)

// When user types rapidly, zoom to cursor position (they're focused on input)
fn detect_typing_zooms(events: &[ZoomEvent]) -> Vec<ZoomRegion> {
    let keypresses: Vec<&ZoomEvent> = events.iter()
        .filter(|e| matches!(e.event_type, EventType::KeyPress))
        .collect();
    
    // 5+ keypresses within 2 seconds = typing session
    let mut regions = Vec::new();
    let mut session_start = 0;
    
    for i in 1..keypresses.len() {
        let gap = keypresses[i].timestamp - keypresses[i-1].timestamp;
        if gap > Duration::from_secs(2) {
            if i - session_start >= 5 {
                // Typing session detected — zoom to cursor position at start
                regions.push(ZoomRegion {
                    start: keypresses[session_start].timestamp - Duration::from_millis(200),
                    end: keypresses[i-1].timestamp + Duration::from_millis(500),
                    center: keypresses[session_start].position,
                    zoom_level: 2.5, // closer zoom for text
                });
            }
            session_start = i;
        }
    }
    regions
}

Phase 3: Zoom Region Merging & Conflict Resolution

fn merge_zoom_regions(mut regions: Vec<ZoomRegion>) -> Vec<ZoomRegion> {
    // Sort by start time
    regions.sort_by_key(|r| r.start);
    
    // Merge overlapping regions (keep higher-confidence one)
    let mut merged = Vec::new();
    for region in regions {
        if let Some(last) = merged.last_mut() {
            if region.start < last.end {
                // Overlap — extend the existing region
                last.end = last.end.max(region.end);
                // Use the center that has more click evidence
                continue;
            }
        }
        merged.push(region);
    }
    
    // Ensure minimum gap between zooms (avoid jarring rapid zooms)
    // FocuSee advice: "slightly extend the interval between each click"
    let min_gap = Duration::from_secs(1);
    let mut final_regions = Vec::new();
    for region in merged {
        if let Some(last) = final_regions.last() {
            if region.start - last.end < min_gap {
                continue; // skip too-close zooms
            }
        }
        final_regions.push(region);
    }
    final_regions
}

Phase 4: Spring-Physics Camera Animation

This is the critical quality differentiator. Linear interpolation looks robotic. Spring physics looks cinematic.

struct SpringCamera {
    position: (f64, f64),   // current camera center
    velocity: (f64, f64),   // current velocity
    zoom: f64,              // current zoom level
    zoom_velocity: f64,
    
    // Spring parameters (tunable)
    stiffness: f64,         // 170.0 (higher = snappier)
    damping: f64,           // 26.0  (higher = less oscillation)
    mass: f64,              // 1.0
}

impl SpringCamera {
    fn update(&mut self, target: (f64, f64), target_zoom: f64, dt: f64) {
        // Damped harmonic oscillator for position
        let dx = target.0 - self.position.0;
        let dy = target.1 - self.position.1;
        
        let spring_force_x = self.stiffness * dx;
        let spring_force_y = self.stiffness * dy;
        let damping_force_x = self.damping * self.velocity.0;
        let damping_force_y = self.damping * self.velocity.1;
        
        let accel_x = (spring_force_x - damping_force_x) / self.mass;
        let accel_y = (spring_force_y - damping_force_y) / self.mass;
        
        self.velocity.0 += accel_x * dt;
        self.velocity.1 += accel_y * dt;
        self.position.0 += self.velocity.0 * dt;
        self.position.1 += self.velocity.1 * dt;
        
        // Same for zoom
        let dz = target_zoom - self.zoom;
        let spring_z = self.stiffness * dz;
        let damp_z = self.damping * self.zoom_velocity;
        self.zoom_velocity += (spring_z - damp_z) / self.mass * dt;
        self.zoom += self.zoom_velocity * dt;
    }
    
    fn get_crop_rect(&self, screen_size: (u32, u32)) -> Rect {
        let crop_w = screen_size.0 as f64 / self.zoom;
        let crop_h = screen_size.1 as f64 / self.zoom;
        Rect {
            x: (self.position.0 - crop_w / 2.0).max(0.0) as u32,
            y: (self.position.1 - crop_h / 2.0).max(0.0) as u32,
            width: crop_w as u32,
            height: crop_h as u32,
        }
    }
}

  3. Implement window focus tracking
  4. Merge + conflict resolution

  1. Implement damped spring for position + zoom
  2. Generate per-frame crop rects from ZoomRegions
  3. Tune stiffness/damping (start: 170/26)
  4. Handle edge cases: clamp to screen bounds

Phase D: Render Integration (1-2 days)

  1. Insert crop+scale step before cursor trail render
  2. Adjust cursor trail coordinates for zoomed viewport
  3. Parallel batch rendering (same rayon pipeline)
  4. User config: zoom level range, sensitivity, enable/disable

⚠️ Critical Gotchas (From Competitor Experience)

  • Cursor coordinates must be transformed: When you crop+scale a frame, the cursor trail coordinates need to be remapped to the new viewport. If zoom center is (500, 300) at 2x, cursor at (600, 400) becomes (200, 200) in the cropped frame, then scaled to output resolution.
  • Don't zoom during drag operations: Retina explicitly bypasses smoothing during drags. If user is dragging a window or selecting text, the camera should NOT try to follow — it creates nausea.
  • Minimum zoom duration: FocuSee users complain about zooms that "start and end too late." Ensure each zoom lasts at least 1.5-2 seconds. Quick flashes are worse than no zoom.
  • Zoom-out should be slower than zoom-in: OBS Zoom-to-Mouse-ULTIMATE offers independent in/out speeds. Cinematic convention: fast zoom in (attention grab), slow zoom out (context restore).
  • Don't zoom when cursor is idle: If cursor hasn't moved for >2s and no clicks, maintain current view. Don't zoom to a static cursor.

Actionable Insights for EasySpecy

🎯 Immediate Next Steps

  1. Add click event capture to your existing mouse hook thread (same thread that captures cursor positions for trail). This is ~20 lines of code — you're already hooking mouse events.
  2. Add active-win-pos-rs to Cargo.toml. On each click, also record the foreground window bounds. This gives you the "zoom to active window" signal for free.
  3. Implement click clustering first — it's the simplest heuristic and gives 80% of the value. Cursorful's "2+ clicks in 3s" rule is battle-tested.
  4. Implement spring camera — the damped harmonic oscillator is ~30 lines of Rust. Start with stiffness=170, damping=26.
  5. Insert crop+scale before cursor trail render — your existing pipeline reads frames, renders trail, pipes to FFmpeg. Insert the crop+scale step between "read frame" and "render trail."

🏗️ Architecture Decision: Post-Processing vs. Real-Time

All competitors that produce high-quality output use post-processing (analyze full recording, then render). Real-time zoom (like OBS scripts) is lower quality because it can't look ahead. Since EasySpecy already does post-processing for cursor trail, auto-zoom fits naturally into the same pass.

Rendering order per frame:

1. Read source frame from captured video
2. Determine zoom state for this timestamp (from pre-computed ZoomRegions + spring camera)
3. Crop source frame to zoom viewport
4. Scale cropped region to output resolution (bilinear or Lanczos)
5. Render cursor trail on zoomed frame (transform trail coords to new viewport)
6. Render click effects on zoomed frame
7. Pipe final frame to FFmpeg encoder

⚡ Performance Consideration

Crop+scale adds CPU cost per frame. But since you're already doing per-frame rendering (cursor trail), the marginal cost is small. The crop is O(1) (pointer arithmetic), and the scale can use SIMD or be done by FFmpeg itself if you pipe the crop coordinates.

Alternative: Let FFmpeg do the crop+scale via -vf "crop=W:H:X:Y,scale=OUTPUT_W:OUTPUT_H" with per-segment filter chains. Generate a filter script with your zoom regions pre-computed. This offloads the heavy scaling to FFmpeg's optimized code.
